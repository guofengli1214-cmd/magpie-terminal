自动执行档位

档位只决定「审阅结论怎么用」，不决定要不要审。每一档都会先过审核 AI。

审阅模型

复审每条将被执行的命令，返回 risk / effect / confirmWhy / reversible。

审阅模型 · 只能选模型
任何档位下都会先由审核 AI 评审，档位只决定评审结果怎么用。这里没有「关闭审阅」：审阅是执行链里固定的一步。
审阅模型不可用（超时 8s / 报错）时，所有命令都要求你确认；降级不会跳过审阅，也不会放行任何命令。

确认卡

在确认卡上常显 AI 的效果评估 默认关（图中是开启态）。开启后确认卡在按钮上方多一行「执行后会发生什么：……」，不悬停也能读到影响。

确认卡右下角的审核角标

颜色即结论，悬停（或键盘聚焦）展开两段：执行后会发生什么 / 为什么需要你确认。

1

会话属于终端，不属于整个应用

标题固定显示当前终端 bash: 41807 与会话总数，副标题才是当前会话名。下拉把会话按终端分组：当前组置顶并展开，其他组折叠可点开。每条会话右侧有来源徽标，本机读 shell（bash / cmd / pwsh 7 / pwsh 5 / WSL），远程读主机名加地址（局域网linux · 192.168.10.24）。

2

切标签就是切会话，没有额外动作

切到 prod-web-01 时，抽屉自动恢复该终端最近一次会话。没有会话就停在空状态，欢迎语和三条例题代替空白。分组列表里能看见其他终端的会话，但点它们不会跨终端跳转：徽标是只读的来源标注。

3

空状态不是错误，是未创建

不预建空会话，不写空记录。用户发第一条消息时才创建，会话列表因此没有无标题条目，也不会出现「0 条消息」的死会话。归属字段随首条消息一起落盘。

4

审阅永远先跑，档位只决定怎么用结论

严格 / 平衡 / 宽松三档都会先把命令交给审核 AI，没有任何一档跳过审阅。档位只决定结论怎么用：严格只放行内置只读，平衡只放行审阅判定只读或幂等的，宽松连可撤销的写操作也放行。审阅模型不可用时退化成「所有命令都要求你确认」，而不是跳过审阅。结论落在确认卡右下角的角标上，悬停展开「执行后会发生什么 / 为什么需要你确认」两段。
